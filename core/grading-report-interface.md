# 标准作业批改报告接口 v1.5

标准《作业批改报告》是日报的优先上游数据源，但**人看的HTML不再作为正常的机器读取接口**。

## 批改阶段固定输出

```text
<assignment-output>/
├── grading-data.json     # 给日报/后续AI读取
├── grading-report.html   # 给人查看；图片仍完整内嵌
└── crops/                # 每道错题的独立原始裁图
```

### grading-data.json
必须包含：
- 总题量 / 正确量 / 错误量 / 正确率；
- 每题正误与答案；
- 每一道错题的题型、考查能力、学生错误表现、错因、关键解析；
- 对应错题裁图的相对路径 `evidence_image_path`。

**禁止在JSON里写base64。** JSON只保留轻量文本和图片路径。

### grading-report.html
仍然是完整、自包含的人看报告；批改Skill的渲染脚本可以把 `crops/` 中图片直接嵌入HTML。这个动作由程序完成，不要求下游日报AI重新解析图片编码。

## L2日报读取
优先读取 `grading-data.json`：
- 总题量 / 正确 / 错误 / 正确率；
- 错题题号与来源；
- 对应 `evidence_image_path`；
- 订正状态（如已有）。

L2不展示题型、能力、错因。已覆盖作业不得重新批改、分析或裁剪。

## L3日报读取
优先读取 `grading-data.json`：
- L2所需全部客观数据与裁图路径；
- 题型；
- 考查能力；
- 学生错误表现；
- 错因；
- 正确/参考答案与关键解析（按日报展示需要取用）。

## 日报HTML生成
日报AI只形成轻量 `daily-data.json`，里面引用已有错题图片路径。最终由 `render_daily.py` 读取图片文件并嵌入自包含HTML。

因此：
- 家长最终拿到的日报HTML仍然包含图片；
- AI推理阶段不再搬运/解析base64；
- 有 `grading-data.json` 时，日报不得为了取数据再打开重型 `grading-report.html`。

## 日报仍保留自主裁图能力
没有经过标准批改报告的材料，例如单词听写、临时小测、督导单独拍摄的一道题等，仍由L2/L3日报按原有保守裁剪协议自行裁图，再把图片路径写入 `daily-data.json`。
